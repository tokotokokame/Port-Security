## 4. Release APK と署名

- 正式署名の鍵と Secrets は未登録（管理者の作業。手順は [RELEASE_SIGNING.md](../RELEASE_SIGNING.md)）。
- そのため **v1.2 の正式な Release APK はまだ作成していない**。main へマージしても、Secrets が登録されるまでビルドは失敗し、公開されない（意図した動作）。
- feature ブランチの CI で作ったデバッグ鍵の APK（証明書 `CN=Android Debug`、SHA-256 `dfdd9494…3704`）は検証用で、公開しない。
- 鍵の登録後に確認すること: `Signing certificate check` が `signing=release pinned=yes`、リリース説明の証明書 SHA-256 が `docs/signing/release-cert.sha256` と一致、実機でオフライン起動と各画面の表示。

## 5. 未解決の課題

1. **署名鍵と Secrets の登録**（F-07）。登録後、`docs/signing/release-cert.sha256` に指紋をコミットする。正式署名の最初のリリースでは、利用者は一度アンインストールが必要。
2. **NEC IX2235 のイベントログリファレンス**（F-05）。公式ページが自動取得を拒否するため未取得。利用者が ELS（10.11.17）を手動で取得できれば、メッセージ（機能名.番号）・条件・取得方法を収録できる。
3. **Palo Alto Networks の出典（SRC-PANW-XPANSE-2021）**。前の作業区間で原文を確認したが、原文の控えは保存していない（この区間では Web 取得の承認が得られず再取得できなかった）。公開前に原文の再確認を推奨。
4. CISA TA14-017A（増幅攻撃）・TA18-106A（Smart Install）は原文を取得できず一部確認。対応する増幅ポート 7 件は一部確認のまま。
5. 攻撃手法 24 件の本文は出典との逐条照合が未実施（content_verification_status=一部確認）。
6. High 以外（Medium 64 / Low 19）の再検証は次版（指示書の範囲どおり）。
7. ATT&CK（Enterprise）の技術が 0 件になったポート 17 件。102・20000/tcp などは ATT&CK for ICS が根拠だが、ICS の技術一覧はデータに取り込んでいない。
8. FortiGate: action の値の一覧、logid（10 桁）の構成、UTM ログ、7.6.3 以降の SSL VPN イベントの出力有無、資料の版（7.4.11 / 7.6.7）以外の版での同一性は未確認。
9. **不要ブランチの削除**（F-23）は利用者の操作が必要（上のコマンド）。
10. SRC-MS-HYPERV-EVTLOG・SRC-NVD-CVE-2023-46604 は本文を取得できず未確認。
11. 実機でのオフライン動作確認は利用者の作業。
